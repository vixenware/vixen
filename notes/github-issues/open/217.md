## Summary

An end-to-end integration test that exercises the full registry dependency pipeline: Cargo.lock parsing, reachability, download, feature resolution, and compilation in topological order.

## Parent issue

Part of #114 (resolve and fetch transitive crates.io dependencies). This is the "definition of done" issue.

## Scope

Build a small binary crate that depends on real crates.io packages with transitive dependencies. The test crates should:
- Have transitive deps (A depends on B depends on C)
- Use features (default features, explicit feature activation)
- NOT require build scripts (tracked in #116)
- NOT require proc macros (tracked in #118)

Candidate dependency sets (to be refined based on what's feasible):
- `itoa` + `ryu` (minimal, almost no deps)
- `memchr` (single crate, has features)
- Something with 10-20 transitive pure-Rust deps

The test should:
1. Create a temp project with Cargo.toml and Cargo.lock
2. Run `vx build` end-to-end
3. Verify the binary was produced
4. Verify all registry crates were fetched and compiled

## Test infrastructure

Add to existing test harness in `crates/vx/tests/harness/scaffold.rs`:
- `create_project_with_registry_deps(&env)` scaffold function
- Pre-generated Cargo.lock (checked into the test fixtures, or generated via cargo during test setup)
