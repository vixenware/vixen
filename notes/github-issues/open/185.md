## Summary

Set up continuous integration on Windows.

## Self-hosted vs GitHub-hosted

**GitHub-hosted** may be sufficient initially — basic compilation and tests don't need special drivers. But if ProjFS testing is needed (Windows VFS), self-hosted may be required since ProjFS is an optional Windows feature that needs to be enabled.

Start with GitHub-hosted, move to self-hosted if needed.

## Scope

### CI jobs

- `cargo check --workspace` (or a platform-appropriate subset)
- `cargo nextest run` — tests
- `cargo clippy --all-targets` — lints

### Platform considerations

- Windows named pipe transport (vx-io) should be tested
- Symlink handling in vx-tarball has Windows-specific code
- No VFS or sandbox tests initially (those come with M120/M10)

- #180 must be fixed first (Windows compilation)
