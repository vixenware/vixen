## Body

## Problem

Cache keys are computed via blake3 hashing of toolchain manifest, args, and source hashes. If the hash domain prefix changes or field ordering changes in a picante tracked function, all caches are silently invalidated across every user. There is no test that detects this.

## Fix

Golden-file test: given fixed inputs (pinned toolchain, known source tree, known args), assert the cache key equals a specific known hex string. Any accidental change to cache key computation becomes a test failure rather than a silent full-rebuild.

This also helps during intentional cache key changes — you update the golden file and can see exactly what changed.
