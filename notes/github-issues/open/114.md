## Body

## Summary

Given a Cargo.lock, resolve and fetch all transitive dependencies from crates.io into the CAS.

## Current state

Registry crate fetching exists but rejects crates with build scripts or proc macros. The crate graph builder handles path deps well but registry dep handling is incomplete.

## Scope

- Parse Cargo.lock for the full dependency graph
- Fetch .crate tarballs from crates.io (or a mirror)
- Store in CAS
- Build the full crate graph with correct dependency edges
- Handle features and conditional dependencies (cfg-gated deps)
- Handle multiple versions of the same crate (version disambiguation)

## Sub-issues

This has been decomposed into smaller, independently testable pieces:

1. **#212** — Tolerate harmless Cargo.toml sections in registry crates (prerequisite for everything)
2. **#213** — Feature resolution: parse `[features]`, resolve defaults, pass `--cfg` to rustc
3. **#215** — Optional dependencies and `dep:foo` syntax
4. **#216** — Platform-specific dependency filtering (`cfg()` predicates)
5. **#217** — Integration test: build real project with transitive pure-Rust registry deps

Dependency graph:
```
#212 (tolerate sections) → #213 (feature resolution) → #215 (optional deps)
                                                      → #216 (cfg filtering)
                           #213 + #215 + #216 ────────→ #217 (integration test)
```
