## Body

## Current behavior

`ActionContext::hermetic_env()` in `service_vfs.rs` unconditionally passes through a flat list of env vars that includes Windows-specific ones (LIB, INCLUDE, LIBPATH, WindowsSdkDir, WindowsSDKVersion) on all platforms, and Linux/macOS ones (HOME) on Windows.

It also applies the same env to all action types (rustc, zig cc, linker) even though they have different needs.

## Desired behavior

- Platform-conditional passthrough: only pass Windows SDK vars on Windows, only pass HOME on Unix, etc.
- Action-aware env: different action types (Rust compile, C compile, link) may need different env vars. For example, `ZIG_LIB_DIR` is currently set ad-hoc in `compile_cc_vfs` rather than being part of the hermetic env setup.
- The current code is harmless (the vars just won't exist on the wrong platform so `env::var` returns Err and they're skipped), but it's confusing and will get worse as more platforms/actions are added.

## Location

`crates/vx-runner/src/service_vfs.rs`, `ActionContext::hermetic_env()`
