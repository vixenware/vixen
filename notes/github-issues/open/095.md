# Issue #95: Lazy VFS tree population for toolchain prefixes

- State: `OPEN`
- URL: https://github.com/bearcove/vixen/issues/95

- Updated: `2026-02-09T23:48:30Z`

## Body

Currently, `populate_toolchain_prefix` (`crates/vx-runner/src/main.rs:469`) eagerly walks every component's `TreeManifest` and calls `add_file_to_prefix` for every single entry:

```rust
for component in &toolchain_manifest.components {
    let tree_manifest = self.cas.get_tree_manifest(component.tree_manifest).await?;
    for entry in &tree_manifest.entries {
        // adds every file to the VFS items HashMap
        self.vfs.add_file_to_prefix(&prefix_id, &path, *blob, *size, *executable).await;
    }
}
```

This materializes the full directory tree structure and file metadata (paths, sizes, permissions, CAS hashes) upfront in the `items: HashMap<ItemId, VfsItem>`. Blob contents are already lazy (fetched on first `read()`), but the tree itself is not.

For large toolchains (rust-std alone has thousands of files), this is unnecessary work — a build typically only touches a fraction of the toolchain. Instead, the VFS could:

- Store the `TreeManifest` hash per component and only resolve directory listings on `readdir()`
- Populate child entries lazily when a directory is first opened/listed
- Keep the blob-on-read behavior as-is

This would reduce startup latency and memory usage for toolchain prefixes.
