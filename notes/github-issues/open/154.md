## Body

## Context

After fixing #128 (env var leakage), `spawn_service()` in vxd now calls `env_clear()` and explicitly passes through only controlled env vars (`PATH`, `HOME`, `VX_TEST`, plus service-specific ones like `VX_HOME`, `VX_STORE`, `VX_RUNNER`).

This works, but the child services (`vx-store`, `vx-runner`, `vx-vfsd`) still read their configuration from environment variables at startup. CLI args would be better.

## Why

- **Auditable**: `ps aux` shows exactly what args a daemon got. Env vars are invisible without `/proc/PID/environ`.
- **No accidental leakage**: Even if `env_clear()` is removed later, CLI args don't inherit from the parent process.
- **Single entry point**: `vx` (the CLI) becomes the only thing that reads env vars and translates them into explicit args for daemons.
- **Cleaner spawning**: `spawn_service()` passes args instead of setting env vars — no need to worry about which env vars each service expects.

## Scope

- `vx-store/src/main.rs`: replace `VX_HOME`, `VX_STORE`, `VX_CAS_BASE` env reads with `--vx-home`, `--listen`, `--cas-base` args
- `vx-runner/src/main.rs`: replace `VX_HOME`, `VX_STORE`, `VX_RUNNER`, `VX_VFSD`, `VX_RUNNER_MOUNT` env reads with CLI args
- `vx-vfsd`: already uses `--listen` etc. — just needs the remaining env var reads converted
- `vxd/src/main.rs`: update `spawn_service()` callers to pass args instead of env var tuples

`PATH` and `HOME` still need to be env vars (they're OS conventions), but all vixen-specific configuration should move to CLI args.
