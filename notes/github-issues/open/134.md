## Body

## Problem

The test suite validates unit-level behavior (cache keys, crate graph construction) but there is no integration test that runs vx build on a real project from cold start and validates the output binary runs correctly.

Without this, you can't detect regressions where cache keys compute correctly but rustc invocation flags are wrong, VFS materialization is incomplete, or output ingestion produces corrupt binaries.

## Scope

- Test fixture: minimal crate with known output (e.g., prints a specific string)
- Cold build → assert binary exists and runs correctly
- Second build → assert zero rustc invocations (all cache hits)
- Modify source → assert only affected crates rebuild
- Test with path deps, registry deps (when M2 lands)

## Notes

Need hermetic test fixtures: canned (Cargo.toml, Cargo.lock, src/) trees checked into the repo, with a local crate mirror or recorded HTTP responses to avoid depending on crates.io availability in CI.
