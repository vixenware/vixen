# Issue #235: Add in-memory chunk cache (Arc<Bytes>) alongside L2 disk cache

## Body

## Problem

We have L2 disk cache for chunks, but no in-memory cache. Repeated reads of the same chunk (common for hot files like libstd metadata, linker scripts, etc.) require disk I/O every time.

## Current state

```rust
// read_chunk_cached() flow:
1. Try L2 disk cache (tokio::fs::read)
2. On miss, fetch from CAS via RPC
3. Write-through to L2 disk
4. Return Vec<u8> (no in-memory retention)
```

## Proposed fix

Add an L1 in-memory cache:

```rust
// Use moka or dashmap
chunk_cache: moka::future::Cache<ChunkHash, Arc<Bytes>>

// In read_chunk_cached():
1. Check L1 memory cache -> hit: return Arc::clone
2. Try L2 disk cache -> hit: insert into L1, return
3. Fetch from CAS -> write L2 + L1, return
```

## Size/eviction

- Chunks are up to 4MB (CDC_MAX_CHUNK)
- LRU with size-based eviction (e.g., 256MB total cap)
- Use `Arc<Bytes>` to avoid copies on cache hit

## Impact

- Eliminates disk I/O for hot chunks
- `Arc::clone` is just a refcount bump
- Compiler workloads with many processes reading the same stdlib see huge wins
