# Issue #30: Migrate JSON serialization to postcard for CAS storage

## Body

## Problem

We're currently using `facet-json` for serializing manifests, tree manifests, and other CAS-stored data structures. JSON has several drawbacks:

1. **Larger size**: Text-based format with key names repeated
2. **Slower parsing**: String parsing vs binary deserialization  
3. **No schema enforcement**: JSON allows arbitrary fields, missing fields
4. **Inconsistent with rapace**: We use facet-postcard for RPC but facet-json for storage

## Current JSON usage

Found in:
- `vx-oort/src/service.rs`: TreeManifest, NodeManifest serialization
- Toolchain manifests stored as JSON in CAS
- Registry crate manifests

Example from `ingest_tree`:
```rust
let manifest_json = facet_json::to_string(&manifest);
let manifest_hash = ManifestHash::from_bytes(manifest_json.as_bytes());
```

## Proposed solution

Switch to `facet-format-postcard` for all CAS-stored data:
- Use `facet_postcard::to_allocvec()` for serialization
- Use `facet_postcard::from_bytes()` for deserialization
- Smaller blobs, faster parsing, schema enforcement via facet

## Migration considerations

1. **Backwards compatibility**: Need to support reading old JSON manifests during transition
2. **Schema versioning**: Already have `schema_version` fields, use them
3. **Testing**: Verify round-trip serialization matches

## Benefits

- 30-50% smaller manifest blobs in CAS
- Faster materialization (less parsing overhead)
- Type-safe deserialization
- Consistent with rapace RPC layer (already uses facet-postcard)

See ~/bearcove/facet/facet-format-postcard for the implementation.
