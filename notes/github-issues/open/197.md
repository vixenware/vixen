## Body

## Question

How different are the rustc invocations for `cargo build` vs `cargo check` vs `cargo clippy`? Understanding this is necessary to support all three modes in vixen.

## What to investigate

- What flags does `cargo check` pass to rustc differently from `cargo build`?
- Does `cargo check` use `--emit=metadata` only (skip codegen)?
- What does `cargo clippy` actually invoke? Is it `clippy-driver` wrapping rustc? Different binary entirely?
- Are there different invocation patterns for `cargo test` (the `--test` harness)?
- What about `cargo doc` — is that rustdoc, not rustc?
- How does this interact with pipeline compilation (#147) — is `check` essentially what the metadata-only phase does?
- What metadata does rustc emit and in what format? (.rmeta files, dep-info, etc.)
- How does this relate to rust-project.json generation (#121) — can we extract the crate graph metadata we need from these invocations?

## Why this matters

If `check` is just "build but only emit metadata," then `vx check` might be nearly free to support once we have pipeline compilation. If clippy requires a different driver binary, we need to acquire and sandbox it separately. Understanding the metadata output is also key for IDE integration — rust-analyzer needs .rmeta files and crate graph info.

## Method

Run `cargo build -vv`, `cargo check -vv`, `cargo clippy -vv`, `cargo test --no-run -vv`, and `cargo doc -vv` on a sample project, diff the rustc/rustdoc command lines, and document:
- Exact flag differences per mode
- Which `--emit` values are used
- Which binary is invoked (rustc vs clippy-driver vs rustdoc)
- What artifacts are produced and where
- What metadata is available and in what format
