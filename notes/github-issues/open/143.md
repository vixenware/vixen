## Problem

Each developer rebuilds from scratch on first checkout. CI rebuilds from scratch on every run. The CAS is local-only.

## Scope

- Remote CAS backend (HTTP blob store, S3, GCS, or custom protocol)
- `vx cache push`: upload local CAS entries to remote
- `vx cache pull`: populate local CAS from remote
- Or transparent: local CAS miss → check remote → populate local
- CI warms the remote cache, developers and subsequent CI runs get cache hits
- Must handle: concurrent writes, partial uploads, authentication

## Notes

The LayeredStorage design in CAS_STORAGE_PLAN.md already has the concept of local + base layers. The base layer needs a remote backend.
