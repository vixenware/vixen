## Summary

Implement an S3-compatible backend for the CAS, enabling remote storage of blobs and manifests.

## Motivation

Local CAS means every machine starts cold. An S3 backend enables:
- CI-warmed caches shared across all developers
- Persistent cache that survives machine rebuilds
- Team-wide deduplication of compiled artifacts
- Foundation for the layered storage architecture (#160)

## Scope

- Implement the CAS storage trait against S3-compatible APIs
- Support: AWS S3, MinIO, R2 (Cloudflare), GCS (S3-compatible mode)
- Operations: get_blob, put_blob, has_blob, get_manifest, put_manifest
- Content-addressed keys map naturally to S3 object keys (e.g., `blobs/{hash}`)
- Authentication: AWS credentials chain (env vars, instance profile, config file)
- Configurable bucket and prefix
- Handle: retries, timeouts, multipart upload for large blobs

## Non-goals (for now)

- Automatic cache population (that's the layered store's job)
- Garbage collection on S3 (use S3 lifecycle policies)
- Encryption at rest (use S3 server-side encryption)
