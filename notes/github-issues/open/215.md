## Background

Cargo's feature system has two kinds of optional dependencies:

1. **Implicit feature** (pre-1.60): `foo = { version = "1", optional = true }` creates an implicit feature named `foo`. Activating feature `foo` includes the dependency.

2. **Explicit dep: syntax** (1.60+): Features can reference deps with `dep:foo`, which does NOT create an implicit feature. Example:
   ```toml
   [features]
   my-feature = ["dep:foo"]
   
   [dependencies]
   foo = { version = "1", optional = true }
   ```

## Scope

- Parse `optional = true` on dependencies (stop rejecting it)
- Parse `default-features = false` on dependencies (stop rejecting it)  
- During feature resolution (#213), determine which optional deps are activated
- Only include activated optional deps in the crate graph edges
- Handle the implicit feature that `optional = true` creates (when not using `dep:` syntax)
- Handle `dep:foo` references in feature definitions
- Prune unactivated optional deps from the dependency edges (they stay in the lockfile but aren't compiled)

## Milestone test
