## Body

## Vision

Never push code that breaks CI. Get instant feedback from builds on all target platforms — macOS, Linux, Windows — from your local machine, before you push.

## How it works

### Trigger

Multiple trigger modes, user-configurable:
- **On save** (non-blocking): file saved → source sync → remote build starts → notification when done
- **On pre-push hook** (blocking): git push → source sync → remote builds → push only if all green
- **On demand**: `vx ci` triggers it manually
- **IDE integration**: editor triggers build on save or on test run

### Flow

```
1. Source sync
   ├─ Incrementally sync changed files to the CAS
   └─ Only delta — files whose content hash changed

2. Fan out to build machines
   ├─ Linux x86_64 builder
   ├─ macOS aarch64 builder (Mac Studio)
   ├─ Windows x86_64 builder
   └─ (any other configured targets)

3. Each builder
   ├─ Pulls sources from shared CAS (layered store)
   ├─ Incremental build — only recompiles affected crates
   ├─ Runs tests (cargo nextest)
   └─ Reports structured results back

4. Results
   ├─ TUI notification: ✅ Linux ✅ macOS ❌ Windows
   ├─ On failure: which platform, which crate, which error
   ├─ Link to full build report (vx explain --web)
   └─ Diagnostics flow back to IDE (if IDE-triggered)
```

### Why this is fast

- **Incremental**: shared CAS means builders already have most artifacts cached. Only changed crates recompile.
- **Source sync is tiny**: content-addressed — only changed file blobs transfer.
- **Parallel**: all platforms build simultaneously.
- **Warm builders**: persistent machines with warm caches, not cold CI containers.

You see: which platform, which crate, the actual diagnostic, and a link to the full build graph.

### Pre-push hook integration

```bash
# .git/hooks/pre-push (or via captain)
vx ci --block --platforms linux,macos,windows
# Exit code 0 = all green, push proceeds
# Exit code 1 = failure, push rejected with diagnostics
```

## Building blocks

This depends on several other pieces coming together:

## Scope (incremental)

### Phase 1: Single-machine `vx ci`
- `vx ci` runs a full build + test locally
- Pre-push hook integration
- Structured pass/fail report

### Phase 2: Remote builders
- Source sync to remote CAS
- Trigger builds on remote machines
- Collect and merge results
- Show unified report

### Phase 3: IDE integration
- On-save trigger (non-blocking)
- Diagnostics flow back to editor
- Per-platform diagnostic annotations
