## Summary

Define deterministic planner builtins and capability policy for EDN rules.

We need a strict, explicit builtin surface for planning:

- graph/fact emission primitives
- Cargo/depfile/build-script parsing adapters
- deterministic transforms and canonical sorting behavior
- explicit denial of nondeterministic operations

## Scope

- Builtin catalog and signatures
- Capability policy (what is allowed vs forbidden)
- Canonical ordering and serialization guarantees
- Threat model and misuse guardrails

## Acceptance Criteria

- Builtin spec doc exists with deterministic semantics for each builtin
- No clock/random/network/raw-fs APIs available in planner runtime
- Determinism test fixtures assert stable output ordering
- Guardrail errors are surfaced with rule/file/line context
