## Body

## Problem

Compilers, linkers, and other tools often read files sequentially. Each read() call that crosses chunk boundaries triggers a fresh RPC roundtrip, even though the access pattern is predictable.

## Current behavior

```rust
// Application does:
read(offset=0, len=64KB)      // fetches chunk 0
read(offset=64KB, len=64KB)   // fetches chunk 1 (sequential!)
read(offset=128KB, len=64KB)  // fetches chunk 2 (sequential!)
// Each read waits for RPC
```

## Proposed fix

Track recent read offsets per ItemId and detect sequential patterns:

```rust
struct ReadState {
    last_offset: u64,
    last_len: u64,
    sequential_count: u8,
}

// In read():
if offset == last_offset + last_len {
    sequential_count += 1;
    if sequential_count >= 2 {
        // Prefetch next 1-2 chunks in background
        let next_chunks = ...; // based on BlobNode
        tokio::spawn(async move {
            for chunk in next_chunks {
                let _ = read_chunk_cached(chunk).await;
            }
        });
    }
}
```

## Implementation notes

- Keep prefetch simple: just fetch into cache, don't return to caller
- Limit prefetch to 1-2 chunks ahead (avoid overfetch)
- Track per ItemId (file handle), reset on seek
- Use existing `read_chunk_cached()` so prefetch populates L1+L2

## Impact

- Hides RPC latency for sequential scans
- Compiler reading .rlib metadata: ~30-50% faster
- Linker scanning object files: similar win
