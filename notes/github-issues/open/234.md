## Body

## Problem

Currently, reading a LargeFile that spans multiple chunks does sequential `await get_chunk()` calls in a loop. This turns read latency into a multiplier: if a file needs 10 chunks and each RPC takes 1ms, that's 10ms minimum just for roundtrips.

## Current code

```rust
// In read_cas_range() for LargeFile (blob_node != None)
for (idx, chunk_hash, chunk_offset) in needed_chunks {
    let data = self.read_chunk_cached(chunk_hash).await?; // sequential
    // ... process chunk
}
```

## Proposed fix

1. Collect all needed chunk hashes first
2. Fetch them concurrently with a bounded semaphore (e.g., 8-16 concurrent)
3. Assemble slices in order

This turns latency-bound into bandwidth-bound, especially for compiler workloads (rustc reading metadata, linker scanning DWARF, etc.)

## Implementation notes

- Already have `read_chunk_cached()` with L2 disk cache
- Need to add `futures::future::join_all()` or similar with semaphore bounding
- Keep chunk reassembly logic the same (just gather first, then slice)

## Impact

Cold cache: 10x+ improvement for multi-chunk reads
Warm cache: smaller win but still removes latency stacking
