## Body

## Summary

Evaluate and implement a virtual filesystem for Windows.

## Options

| Backend | Type | License | Notes |
|---------|------|---------|-------|
| ProjFS (Windows Projected File System) | Kernel driver (built into Windows 10+) | Microsoft | Used by VFS for Git. Enable via Windows Features. |
| WinFSP | FUSE-compatible user-mode FS | GPLv3 with commercial option | Mature, well-documented, FUSE API compatibility layer. |
| Dokany | User-mode FS | LGPL/MIT | Less maintained than WinFSP. |

## Considerations

- ProjFS is the "blessed" Microsoft approach but has a different model (placeholder/hydration) than FUSE
- WinFSP provides FUSE API compat which might share more code with our Linux FUSE implementation
- Need to consider: does the VFS model (read-only CAS-backed) map well to ProjFS's placeholder model?

## Scope

- Research and prototype both ProjFS and WinFSP
- Choose one and implement the Vfs trait for Windows
- Wire into vx-vfs platform dispatch (currently returns Unsupported for non-mac/linux)
