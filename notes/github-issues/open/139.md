## Body

## Problem

Many real projects use [patch.crates-io] to override upstream crates with local forks during development. The manifest parser currently rejects this. Without it, vixen cannot build any project with patched dependencies — which is common in workspaces that maintain forks.

## How it works

When [patch.crates-io] maps crate-name to a path, the lockfile entry for that crate changes from source = "registry+..." to a path source. The crate graph builder needs to resolve patched crates from the local path instead of the registry.

## Scope

- Parse [patch.crates-io] from Cargo.toml
- When resolving a crate that has a patch entry, use the path source
- Lockfile entries for patched crates have different source metadata
