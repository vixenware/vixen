# Issue #16: Implement file watching in vxd for true incremental builds

- State: `OPEN`
- URL: https://github.com/bearcove/vixen/issues/16

- Updated: `2026-02-09T21:29:00Z`
- Labels: P1, area/build-graph

## Body

Currently, vx-aether has no file watching. Every build unconditionally:
- Walks all source trees to discover modules
- Hashes all discovered files
- Creates fresh picante inputs

This means there's **no incrementality at the file level** - we always assume everything might have changed.

## What should happen (buck2-style daemon)

### 1. File watching while running
- Use `notify` or similar to watch workspace files
- Track which files have been modified since last build
- Only re-walk/re-hash changed files and their transitive dependents

### 2. Mtime checking on startup
When aether starts up (or restarts after being killed):
1. Load persisted picante cache (see #15)
2. For each file in the previous build:
   - Check mtime against recorded value
   - If mtime unchanged: Trust the cached hash
   - If mtime changed: Re-hash and update picante input
3. Detect newly added/deleted files

### 3. Integration with picante

Instead of this (current code at `service.rs:401-408`):
```rust
// Always walks and hashes everything
let closure_paths = vx_rs::rust_source_closure(&crate_root_abs, &graph.workspace_root)?;
let closure_hash = vx_rs::hash_source_closure(&closure_paths, &graph.workspace_root)?;
```

We should:
```rust
// Check if crate_root or any dependencies changed via file watcher
if !file_watcher.has_changes_since_last_build(&crate_root_abs) {
    // Use cached closure_hash from picante - instant!
} else {
    // Re-walk only changed portions
    // Re-hash only files with changed mtime
}
```

## Performance impact

**Without file watching:**
- Clean rebuild of 50-crate workspace: Walk + hash all files
- Change 1 file: Walk + hash all files (same cost as clean build!)

**With file watching:**
- Clean rebuild: Walk + hash all files (first time only)
- Change 1 file: Re-hash 1 file + transitive dependents
- Change nothing: No file I/O at all - instant cache key computation

## Implementation notes

- This works best with picante persistence (#15) - need to persist mtime + hash mappings
- File hashing should become an Action in the action graph (#13)
- Similar to buck2's watchman integration
- On macOS: Use FSEvents, Linux: inotify, Windows: ReadDirectoryChangesW
