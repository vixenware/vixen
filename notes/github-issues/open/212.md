# Issue #212: Tolerate harmless Cargo.toml sections in registry crates

- Updated: `2026-02-10T19:15:10Z`

## Body

## Summary

Stop rejecting registry crate Cargo.toml files that contain sections we don't need to act on. Currently `vx-manifest` rejects `[dev-dependencies]`, `[features]`, `[[test]]`, `[[bench]]`, `[[example]]` at parse time, but for registry crates we never compile tests/benches/examples and don't need dev-deps.

## Parent issue

Part of #114 (resolve and fetch transitive crates.io dependencies).

## Current state

`finalize_with_registry` already uses `facet_cargo_toml::CargoToml` directly (bypassing `vx-manifest`'s strict validation), so registry crate parsing partially avoids these rejections. But the strict rejections in `vx-manifest` block path crates that legitimately have these sections, and the overall approach needs a clear distinction between "parse for building" vs "parse for graph construction."

Key locations:
- `crates/vx-manifest/src/lib.rs` lines 286-350 — the rejection checks
- `crates/vx-rs/src/crate_graph.rs` lines 806-810 — `finalize_with_registry` uses raw `facet_cargo_toml`

## Scope

- For registry crates: ignore `[dev-dependencies]`, `[build-dependencies]`, `[[test]]`, `[[bench]]`, `[[example]]`, `[workspace]` sections instead of rejecting
- For path crates: keep existing behavior (or relax selectively where it makes sense)
- Ensure `[features]` sections are parsed and stored (not rejected) — the data is needed by #213 (feature resolution)
- `proc-macro = true` in `[lib]` remains rejected for now (tracked in #118)

## Milestone test

Parse the Cargo.toml of `itoa 1.0.14` (which has `[dev-dependencies]` and `[[bench]]`) without error during `finalize_with_registry`.
