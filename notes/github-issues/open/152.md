## Summary

Define where vixen-specific configuration lives. What is the project configuration file?

## The tension

Vixen builds Rust projects defined by Cargo.toml. But vixen has its own knobs that don't belong in Cargo.toml:
- Profile overrides
- Sandbox configuration
- Feature selection defaults
- Linker selection
- Build cache settings
- Custom build rules (if #150 lands)

## Options

### 1. Cargo.toml only (maximum compat)
Use `[package.metadata.vx]` for vixen-specific settings. Pro: one file. Con: limited by TOML, feels like a hack.

### 2. vx.styx (Styx config file)
A separate config file in the project root. Pro: full Styx expressiveness, typed schemas. Con: another file, Styx is our own language.

### 3. vx.mag (Magma rule file)
If #150 (rule language) lands, configuration and rules could live in the same file. Pro: unified. Con: depends on the rule language experiment.

### 4. Cargo.toml + optional vx.styx overlay
Read everything from Cargo.toml by default. If vx.styx exists, it can override/extend. Pro: works with zero config for simple projects, power when needed.

## What needs configuring?

- Target selection (default target triple)
- Profile settings (beyond Cargo defaults)
- Linker selection (per-target)
- Feature defaults (which features to enable by default)
- Sandbox policy overrides (e.g., allow network for specific build scripts)
- Remote cache endpoint
- Toolchain pinning (beyond rust-toolchain.toml)
