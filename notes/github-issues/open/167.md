## Body

## Problem

Currently, daemons die on startup errors and errors are propagated through stderr parsing and process death. This is fragile and doesn't provide clean error messages to users.

## Proposed Architecture

### Core Principles

1. **Nothing is fatal** - daemons never self-terminate
2. **vxd is boss** - only vxd decides when processes die
3. **Errors propagate through RPC** - structured, not logs
4. **Boot before serving** - initialization happens through RPC

### Boot Protocol

Each daemon (vx-store, vx-vfsd, vx-runner) implements a `boot()` RPC call:

1. Daemon starts, binds RPC socket, waits
2. Parent calls `boot()` with initialization params
3. Daemon performs initialization (mount VFS, connect to deps, etc.)
4. Returns `Ok(())` on success or `Err(details)` on failure
5. Daemon stays alive regardless of outcome
6. Tracks boot state: `NotBooted`, `Booted`, `BootFailed(error)`

### Virtual Connections (Roam Feature)

Use Roam's virtual connection feature for cleaner protocol:

1. Initial connection provides only a **warmup service**
2. Client calls `boot()` on the warmup service
3. If boot succeeds, client establishes **sub-connection** to the actual service
4. If client tries to establish sub-connection before boot → error: "boot first"

This keeps the protocol clean - boot is separate from the main service.

### Error Propagation Flow

Example: vx-vfsd mount failure

**Old way (current):**
1. vx-vfsd tries to mount during startup
2. Mount fails
3. vx-vfsd prints to stderr and dies
4. vx-runner sees process died, parses stderr
5. vx-runner dies, prints to stderr
6. User sees logs

**New way:**
1. vx-vfsd starts, binds socket
2. vx-runner calls `vfsd.boot(mount_path)`
3. vx-vfsd tries to mount, fails
4. vx-vfsd returns `Err("mount failed: invalid filesystem")` through RPC
5. vx-runner's boot fails, returns error to vxd through RPC
6. vxd returns error to vx CLI through RPC
7. User sees clean error message
8. **No processes died**

### Implementation Steps

1. **Add boot RPC to each daemon**
2. **Use Roam virtual connections**
3. **Track boot state in each daemon**
4. **Update vxd to orchestrate boots**
5. **Remove fatal exits**

### Benefits

- Clean, structured error messages for users
- No process death races or stderr parsing
- Daemons can be introspected even when broken
- Clear separation: vxd controls lifecycle
- Better testability

## Current Issue

While debugging vx-vfsd mount failure with FSKit (needs `--FF` flag), error propagation issues make diagnosis difficult, hence this architectural improvement.
