## Body

## Summary

Evaluate `cfg()` predicates to correctly include or exclude target-gated dependencies.

## Parent issue

Part of #114 (resolve and fetch transitive crates.io dependencies).

## Current state

`[target.'cfg(...)'.dependencies]` sections in Cargo.toml are not parsed at all. The lockfile contains all platform variants, so without filtering we'd either try to compile deps we don't need or miss deps we do need.

## Scope

- Parse `[target.'cfg(...)'.dependencies]` sections from Cargo.toml
- Parse `[target.<triple>.dependencies]` sections (exact target match)
- Implement a cfg predicate evaluator that takes a target triple and evaluates:
  - `cfg(unix)`, `cfg(windows)`, `cfg(target_os = "macos")`, `cfg(target_os = "linux")`
  - `cfg(target_arch = "x86_64")`, `cfg(target_arch = "aarch64")`
  - `cfg(target_family = "unix")`
  - `cfg(all(...))`, `cfg(any(...))`, `cfg(not(...))`
  - `cfg(target_env = "gnu")`, `cfg(target_env = "musl")`
  - `cfg(target_pointer_width = "64")`
- During graph construction, only include deps whose cfg predicates match the build target
- The cfg evaluator should work from the target triple string (e.g., `aarch64-apple-darwin`) without needing rustc

## Milestone test

A crate with `[target.'cfg(unix)'.dependencies]` containing `libc` builds on macOS/Linux with libc included, and a crate with `[target.'cfg(windows)'.dependencies]` containing `winapi` does NOT try to fetch/compile winapi on macOS/Linux.
