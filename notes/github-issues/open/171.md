## Summary

Integrate with cargo-llvm-cov to generate LLVM source-based code coverage reports.

## How LLVM coverage works

1. Compile with `-C instrument-coverage` (rustc flag)
2. Run the binary — it writes `.profraw` files
3. Merge profiles: `llvm-profdata merge *.profraw -o merged.profdata`
4. Generate report: `llvm-cov report/show/export` against the binary + profdata

## Scope

### vx coverage

- `vx coverage` — build with coverage instrumentation, run tests, generate report
- `vx coverage --html` — HTML report
- `vx coverage --lcov` — LCOV format for CI tools (Codecov, Coveralls)
- `vx coverage --json` — machine-readable

### Compilation changes

- Add `-C instrument-coverage` to rustc flags when coverage is requested
- Coverage builds are a separate profile (different cache key — instrumented code is different)
- Collect `.profraw` files from test execution
- Run `llvm-profdata merge` and `llvm-cov` from the toolchain sysroot

### Integration with test runner

Coverage depends on test execution (#167). The flow is:
1. Build with instrumentation (vx build --coverage)
2. Run tests (vx test, collects .profraw)
3. Merge + report (vx coverage report)

### Open questions

- Do we vendor llvm-profdata and llvm-cov, or use them from the Rust toolchain's llvm-tools component?
- Should coverage data be cached in the CAS? (Probably not — coverage changes with any source change)
- How to handle coverage across multiple test binaries (merge all .profraw before reporting)
- Integration with cargo-llvm-cov directly vs reimplementing the pipeline?
