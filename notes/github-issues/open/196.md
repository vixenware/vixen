## Body

## Problem

Currently, action outputs are ingested into the CAS only after the action finishes. The full cycle is:

1. Action writes files to VFS (held in memory)
2. Action exits
3. VFS output files are read back and ingested into CAS
4. Next action that depends on these outputs can start

Step 3 is dead time — the bytes are sitting there ready but we wait for the action to fully exit before moving them.

## Proposal

Stream completed output files to the CAS as they're written, before the action finishes:

- When a file in the output prefix is closed (or fsync'd) by the action, start ingesting it into CAS immediately
- By the time the action exits, most or all outputs are already in the CAS
- The "ingest outputs" phase after action completion becomes a no-op or near-instant

### How it works

```
rustc writes foo.rlib → VFS intercepts close() → background task ingests to CAS
rustc writes foo.rmeta → VFS intercepts close() → background task ingests to CAS
  ... meanwhile rustc is still running, writing more files ...
rustc exits → all outputs already in CAS → next action starts immediately
```

### Considerations

- Only ingest on close/fsync, not on every write (files may be written incrementally)
- rustc may write a file, close it, then rewrite it — need to handle this (last close wins, or only ingest after action exits for safety)
- Some files are written atomically (write to .tmp, rename to final) — need to handle rename
- This is an optimization, not a correctness change — can fall back to post-action ingestion if streaming fails
- Pairs well with the disk spill (#194): spill to disk, then stream from disk to CAS in background
