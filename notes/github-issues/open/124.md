## Summary

Implement sandboxing for build actions on Windows.

## Options

| Backend | Capabilities | Notes |
|---------|-------------|-------|
| Job objects | CPU/memory limits, process tree kill | No filesystem isolation |
| AppContainer | Filesystem isolation, network isolation | Used by UWP apps, lower-level API |
| Windows Sandbox | Full VM isolation | Too heavy for per-action use |
| Restricted tokens | Reduced privilege set | Can combine with job objects |

## Considerations

- Wardstone does not support Windows yet (tracked upstream)
- May need to implement directly against Win32 APIs
- AppContainer provides the closest equivalent to seatbelt/landlock
- Job objects are useful for timeout/process-tree enforcement regardless

## Scope

- Research AppContainer for filesystem + network isolation
- Implement timeout via job objects (process tree kill on deadline)
- Same policy model as macOS/Linux: VFS mount only, no network
