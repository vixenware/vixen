## Summary

Implement a layered CAS that checks memory first, then disk, then remote (S3), promoting entries to faster layers on access.

## Architecture

```
┌─────────────────┐
│   Memory Cache   │  ← hot blobs, bounded by size (e.g., 512 MB)
│   (LRU eviction) │
├─────────────────┤
│   Disk Cache     │  ← warm blobs, ~/.vx/cas/
│   (current impl) │
├─────────────────┤
│   S3 Backend     │  ← cold blobs, shared across machines
│   (remote)       │
└─────────────────┘
```

## Behavior

**Read path** (get_blob):
1. Check memory → hit? return immediately
2. Check disk → hit? promote to memory, return
3. Check S3 → hit? promote to disk + memory, return
4. Miss → error (blob doesn't exist anywhere)

**Write path** (put_blob):
1. Write to disk (durable)
2. Insert into memory cache
3. Async push to S3 (background, non-blocking)

## Scope

- Layer abstraction: trait with get/put/has operations
- Memory layer: bounded LRU cache (size-based eviction)
- Disk layer: current filesystem CAS (already exists)
- Remote layer: S3 backend (#159)
- Compose layers with read-through / write-through semantics
- Promotion on access (cold → warm → hot)
- Background push to remote (don't block builds on S3 uploads)

## Configuration

```
# vx.styx or similar
store {
  memory { max-size "512MB" }
  disk { path "~/.vx/cas" }
  remote { 
    backend "s3"
    bucket "my-team-vixen-cache"
    prefix "v1/"
  }
}
```
