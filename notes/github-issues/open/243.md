# Issue #243: Error propagation: stuck-mount diagnostic doesn't reach test output

- URL: https://github.com/bearcove/vixen/issues/243
- Created: `2026-02-11T21:15:56Z`
- Updated: `2026-03-06T16:55:49Z`
- Labels: P2, area/vfs, area/diagnostics

## Body

When vx-vfsd detects unkillable processes (uninterruptible sleep on dead FSKit mount) and bails, the error message only shows up as `Error: "mount point is unusable..."` on stderr of the vx-vfsd process.

The test runner sees:
```
vx: vxd unreachable after 5s at unix:/.../vxd.sock: connection failed: Connection refused
```

The actual root cause (5 stuck processes, reboot needed) never makes it to the test output.

## Problems

1. **No tracing target** — the error is printed via eyre/eprintln, not through tracing, so there's no process attribution
2. **Error doesn't propagate** — vx-vfsd exits with status 1, vx-runner sees "vx-vfsd exited with exit status: 1", vxd sees "vxd unreachable after 5s". The original diagnostic is lost at each hop.
3. **vxd timeout** — vxd waits the full 5s timeout even though vx-runner already died

## What should happen

The stuck-mount diagnostic should flow up: vx-vfsd → vx-runner → vxd → test setup, with the original error message preserved. The test should fail immediately with a clear message about the stuck processes, not a generic connection timeout.

## Related

This was found while implementing the pre-flight lsof cleanup and vx-reaper in the VFS smoke test work.
