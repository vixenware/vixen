## Body

## Problem

Integration tests (which spawn vxd, mount VFS, do real builds) require setup scripts (start daemons, prepare fixtures, etc.). Unit tests don't. Currently there's no separation — running any tests may trigger heavyweight setup that's only needed for integration tests.

## Goal

- \`cargo nextest run\` with no filter runs unit tests fast, no setup scripts
- Integration tests live in separate packages (or are filterable) so setup scripts only run when needed
- Setup scripts are configured via nextest's \`profile.<profile>.scripts\` with \`filter = 'rdeps(...)'\`

## How nextest supports this

Nextest has [setup scripts](https://nexte.st/docs/configuration/setup-scripts/) with per-package filtering:

\`\`\`toml
# .config/nextest.toml

[scripts.integration-setup]
command = './scripts/setup-integration.sh'

[[profile.default.scripts]]
filter = 'rdeps(vixen-integration-tests)'
setup = 'integration-setup'
\`\`\`

This means the setup script only runs when tests from the \`vixen-integration-tests\` package (or packages depending on it) are in the test run. Pure unit tests skip it entirely.

## Scope

- Move integration tests to a dedicated crate (e.g., \`crates/vixen-integration-tests/\`)
- Keep unit tests in their respective crates as \`#[cfg(test)]\` modules
- Configure nextest setup scripts with \`filter = 'rdeps(vixen-integration-tests)'\`
- Setup script handles: daemon startup, fixture preparation, cleanup
- Unit tests remain fast and isolated — no daemon, no VFS, no network
