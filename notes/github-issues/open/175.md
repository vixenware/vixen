## Body

## Problem

As we add more platform/environment metadata (like CommandLineTools version for macOS), we're hitting function argument explosion. For example, `execute_action` is already using `#[allow(clippy::too_many_arguments)]` and we keep adding more parameters.

Currently threading individual values like:
- `workspace_root`
- `target_triple`
- `profile`
- `macos_commandlinetools_version` (added in #169)

## Future Direction

The build system will move towards being scriptable, which means:
- Metadata will come from different sources (not just Rust types)
- We need "bags of metadata" rather than strongly-typed structs
- Current approach of adding function parameters doesn't scale

## Proposed Solution (TBD)

Options to consider:
1. **BuildContext struct** - bundle related parameters
2. **Metadata bags** - untyped key-value maps for extensibility
3. **Action-embedded metadata** - move metadata into Action variants themselves

This needs design discussion around scriptability requirements.
