# Issue Audit - 2026-03-06

This note records issues that appear already implemented, partially implemented,
or clearly still open after auditing the codebase.

## Confirmed Close Candidates

### `#123` Windows VFS: evaluate ProjFS vs WinFSP

Recommendation: close.

Evidence:

- `crates/vx-vfs/src/windows.rs` implements a Windows backend around ProjFS.
- `crates/vx-vfs/Cargo.toml` depends on `windows-projfs`.
- `crates/vx-vfs/src/lib.rs` dispatches to `windows::mount(...)` on Windows.

This looks like the evaluation is over and the implementation choice was
ProjFS.

### `#131` Cache key stability: golden-file tests for cache key computation

Recommendation: close.

Evidence:

- `crates/vxd/src/tests.rs` contains explicit golden cache-key tests for:
  - `compile_bin`
  - `compile_rlib`
  - `compile_rlib_with_deps`
  - `compile_bin_with_deps`
  - `cc_compile`
  - `cc_link`
  - `compile_bin_with_session`
- Several files explicitly reference issue `#131`.

This is not just partially present; the exact test style requested by the issue
exists.

### `#167` Implement proper error propagation with boot RPC and virtual connections

Recommendation: close.

Evidence:

- `crates/vx-io/src/boot.rs` defines the boot protocol, `BootGate`,
  `BootResult`, `boot_and_connect`, and virtual-connection flow.
- `crates/vx-store/src/main.rs`, `crates/vx-runner/src/main.rs`,
  `crates/vx-vfsd/src/main.rs`, and `crates/vxd/src/main.rs` all wire daemons
  through `BootGate` / `BootDispatcher`.
- `crates/vx/src/main.rs` talks to the root connection via the boot service.

This issue appears to have become the current architecture.

### `#221` RulePlan -> ActionGraph lowering bridge

Recommendation: close.

Evidence:

- `crates/vxd/src/action_graph.rs` implements:
  - `ActionGraph::from_rule_plan(...)`
  - `ActionGraph::from_rule_plan_executable(...)`
- `crates/vxd/src/service.rs` has `VX_RULE_PLAN_BRIDGE` /
  `VX_RULE_PLAN_EXEC` integration.
- Lowering failures are provenance-mapped.
- Topology/edge-kind metadata flows into reports.

This matches the issue far more than "scaffolding only".

## Strong Split / Update Candidates

### `#183` vixen does not compile on macOS or Windows

Recommendation: update or split, not close.

Evidence:

- `cargo check --workspace` succeeded on Darwin on 2026-03-06.
- The repo now has explicit macOS and Windows VFS modules and platform gating.

Conclusion:

- The macOS half of the issue looks stale.
- Windows may still be incomplete, but this should no longer be one combined
  "macOS or Windows" blocker.

### `#152` Project configuration: vx.styx / vx.mag / Cargo.toml-only?

Recommendation: keep open, but update the body.

Evidence:

- `crates/vx-project/src/lib.rs` parses `vx.styx`, searches for it, validates
  it, and falls back to `Cargo.toml`.
- `crates/vxd/src/service.rs` checks for `vx.styx` first and builds C projects
  from it.
- Rust via `vx.styx` is still explicitly TODO.

Conclusion:

The repo has already made a partial product decision. The issue body should be
updated to reflect the current state instead of asking the original question as
if nothing exists.

### `#206` Separate integration tests from unit tests

Recommendation: keep open.

Evidence:

- `.config/nextest.toml` exists and uses setup scripts.
- But the scripts run with `filter = 'all()'`, not an integration-only filter.
- Tests still live under `crates/vx/tests/...`, not a dedicated integration
  package.

Conclusion:

There is progress here, but the acceptance criteria are not met.

## Clearly Still Open

These have visible groundwork, but not enough to justify closure:

- `#154` daemon config env vars -> CLI args
  - CLI args exist in places, but `VX_HOME`, `VX_STORE`, `VX_RUNNER`, etc. are
    still actively used.
- `#116` build script execution
  - `vx-rs/src/build_script.rs` exists, but the crate graph and tests still
    treat build scripts as unsupported/not wired through.
- `#118` proc macro compilation and loading
  - proc macros are still rejected in the crate graph and integration tests
    assert that rejection.
- `#220`
  - capability/policy/runtime work exists, but the issue asks for a fuller spec
    and determinism contract.
- `#222`
  - parity comparison exists, but the issue also asks for fixture corpus and CI
    gating.
- `#226`, `#227`
  - parser/runtime/conformance groundwork exists in `vx-plan`, but not enough
    evidence yet that the spec/conformance issues are fully done.
