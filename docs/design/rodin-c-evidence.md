# Rodin agenda C evidence

Generated by `cargo run -p rodin-survey`. The survey fetches crates.io sparse-index files sequentially, with User-Agent `rodin-survey/0.1.0 (https://github.com/bearcove/vx)`, and caches them under `target/rodin-survey-cache/` so repeat runs are offline. Seed crates: axum, tokio, serde, clap, reqwest, syn, rand. Closure cap: 400 crates. Actual closure size: 400 crates.

## Method

- Walk: start from the seed crate names, fetch each sparse-index file, parse every JSONL version row with `facet-json`, enqueue dependency names from `package` when present or `name` otherwise, and stop at the closure cap.
- Measurement A: ignore yanked versions for block construction, sort remaining versions by semver order, normalize each row to resolution metadata (`deps` by name/req/features/optional/default_features/target/kind plus merged `features`/`features2` maps), and count contiguous runs of identical metadata. Yanked counts are reported separately.
- Measurement B: choose the 20 closure members with the most non-yanked versions, collect real requirement strings targeting those packages from the fetched index rows, convert them through `rodin_facts::VersionSet::from_req`, and run 100 chained `Region::subtract` exclusions from a full version box plus a companion `Region::intersect` chain.

## Verdict

The data does not support the strong agenda C falsifier target, "block-ratio brutal, hundreds-to-few, for almost all packages." The measured collapse is only 1.880944 versions/block overall: median 1.75, p90 5, and just 28.75% of crates have <=5 blocks, with 15309 non-yanked versions becoming 8139 metadata blocks. ## Round 2

Round 2 keeps the Round 1 closure and sparse-index cache fixed, then asks whether the counterexamples are mostly lockstep family edges or whether the useful granularity is per-edge rather than whole-manifest.

### Method

- Lockstep detection: for each unique `parent -> actual-dep` edge, scan the parent's non-yanked version sequence. A row is lockstep when its requirement parses as exactly one comparator, either exact `=x.y.z` or caret/full-triple `^x.y.z`/`x.y.z`, and that comparator version equals the parent version. An edge is classified lockstep only when every present row is lockstep and it appears in at least two parent versions.
- Per-edge blocks: for each non-lockstep `parent -> actual-dep` edge, count contiguous runs across the full non-yanked parent version sequence using only that edge's metadata (`req/features/optional/default_features/target/kind`). Absence is a state, so add/remove transitions count.
- Post-fusion whole-manifest blocks: repeat Round 1's whole-manifest block count, but drop lockstep dependency rows from the metadata identity, leaving the feature maps unchanged.

### Round 2 verdict

Family fusion finds real structure: 83 of 4513 unique edges are lockstep (1.839131% by edge count, 3.501598% by dep rows). It improves whole-manifest blocks from 8139 to 7894, and overall versions/block from 1.880944 to 1.939321, but that is still not a big collapse: fused median is 1.833333, p90 is 5.333333, and only 30.5% of crates have <=5 blocks. Per-edge granularity is much stronger: 4430 non-lockstep edges collapse to 23207 edge blocks over 310719 parent-version observations, with median 11, p90 41.666667, max 220, and 77.291196% of edges at <=5 blocks. So family fusion alone does not rescue the whole-manifest frontier bet; per-edge granularity is the only round-2 hypothesis that looks empirically useful, and it points away from whole-manifest metadata blocks as the primary volume unit.
