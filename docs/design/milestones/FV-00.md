# FV-00 design packet: preserve and integrate the proven baseline

Status: committee candidate, 2026-07-15.

Controlling roadmap: [Vix full-vision milestones](../vix-full-vision-milestones.md),
milestone `FV-00` only. This packet does not authorize or begin `FV-D1`.

## Outcome and stop condition

Produce one clean, pushed Facet lineage containing the completed Vix runtime,
Rodin, Taxon, and facet-core work on top of the current local Facet main-line
commit. Preserve the demo's actual proof boundary: `RealProcessBackend`,
`FakeFetchBackend`, prepared sparse rows, and the Cargo oracle remain labelled
evidence paths, not production defaults.

`FV-00` stops after the integrated lineage, authority corrections, complete
verification ladder, pushed refs, and post-diff committee approval. It does not
change fetch identity, observe crates.io, or implement any `FV-D1`/`FV-D2`
behavior.

## Authority and invariants

No new runtime data type or semantic authority is introduced by this milestone.

- Facet owns Vix, Rodin, Weavy, tests, and Cargo-oracle semantics.
- Vixen owns this planning packet and the private product documentation.
- Cargo remains an executable oracle only.
- The Vix-language Rodin kernel remains the only production solver.
- The normal Store/scheduler/journal remains the only memo and receipt
  authority.
- Existing fixtures and host-trusting backends remain explicit demo/test
  evidence. Integration must not relabel them as production.
- The current local main-line Dibs commit belongs to the user and is preserved
  as the new lineage's first parent.
- No reset, rebase, revert, checkout-overwrite, squash, generated-file edit, or
  discarded checkpoint is permitted.
- An unexpected regression is fixed forward and committed. A red gate is
  recorded as a useful negative result; it is not bypassed.

## Proposed implementation

### 1. Create the integration lineage

Create a dedicated Paseo worktree and branch `vix/full-vision-fv00` from exact
Facet local `main` tip `1603fef97536994f3f2105afc00cd21a3cbf566c`.
The branch name is currently unused locally and on `origin`.

Merge `vix-demo1-ladder-2` with a merge commit. Do not separately merge
`forward-integration-vix-weavy-rodin`, Taxon, or `rodin`; they are already
ancestors of the facet-core tip. Preserve local `main` as first parent and the
91-commit completed lineage as second parent.

Before changing code, verify that the actual merge tree matches the clean
synthetic preview. If it does not, record the new external-state delta and
return the changed conflict shape to committee review.

### 2. Reconcile authority wording

In Vixen, make the smallest forward documentation correction:

- add a top-level supersession banner to `docs/design/rodin-in-vix.md` pointing
  to repository `CLAUDE.md` and Facet `rodin/EXECUTION-PLAN.md`, while preserving
  the historical body;
- update `CLAUDE.md` so the retired Rust resolver crates are described as
  pruned historical scaffolding rather than present directories. Preserve the
  directives that new work goes into Vix and Cargo is the behavioral oracle.

Do not edit generated files or rewrite the historical research record.

### 3. Fix only combined-tree regressions

Run the ladder below on the integration branch. Any required fix must preserve
the merged behavior and land as a separate forward commit. Do not remove a
fixture, weaken a negative, disable an execution lane, or turn a failure into a
typed unsupported result unless the current specification requires that exact
boundary.

### 4. Record and publish evidence

After every gate and post-diff review is green:

- add the exact Facet integration tip, Vixen documentation tip, commands,
  selected-test counts, results, and residual boundaries to this packet;
- push `vix/full-vision-fv00` to Facet `origin`;
- push Vixen `rodin-workspace-scope` to its `origin`;
- do not update Facet `origin/main` in this milestone. The pushed integration
  branch is the reviewable lineage; changing the protected/main release line is
  a distinct maintainer action.

## Negative controls

- The local main-line Dibs commit is present in the integrated ancestry and
  remains byte-for-byte unchanged by Vix merge fixes.
- Taxon and facet-core missing/wrong `cc` tests still fail at the capability
  boundary.
- Changed archive/build-script tests still fail for the authored reason.
- Irrelevant workspace edits produce the existing reuse proof rather than a
  recompute-and-compare result.
- Cargo is absent from the production-demo input arguments and remains only in
  separately invoked oracle tests.
- `RealProcessBackend` and `FakeFetchBackend` remain discoverable as
  demo/evidence types and are not selected by a production default.
